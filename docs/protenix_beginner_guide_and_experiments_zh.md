# 第一部分 · 项目介绍

## 0. 一句话总结

**Protenix = 字节跳动开源的、可以自己训练的 PyTorch 版 AlphaFold 3。** 你给它几条"分子说明书"（蛋白质 / DNA / RNA 的序列、小分子药物的化学式、金属离子），它输出这些分子**组装在一起时的三维原子坐标**，并告诉你它对每一部分有多大把握。✅

类比：如果把蛋白质序列看成一串"代码"，那三维结构就是这串代码"编译运行"后的实际形态；Protenix 是一个**不用真的做实验、直接从代码预测运行形态**的模型。

---

## 1. 生物学速成：你需要知道的最少背景

📘 以下均为通识。

### 1.1 蛋白质 = 20 种字母拼成的长链，会自己折叠

- **氨基酸**：20 种标准"积木"，各用一个字母表示（如 `M` 甲硫氨酸、`G` 甘氨酸）。
- **蛋白质**：几十到几千个氨基酸首尾相连的长链，写下来就是一个字符串，例如 `MAQGSHQIDF...`。每个氨基酸在链里叫一个**残基（residue）**。
- **折叠**：这条链在水里会自发蜷缩成一个特定的三维形状。**形状决定功能**——酶的口袋形状决定它能催化什么反应；抗体的"指尖"形状决定它能抓住哪个病毒。
- 序列 → 结构这件事极难算：链很长、自由度极高。这就是著名的"蛋白质折叠问题"，AlphaFold2（2021）首次把它做到接近实验精度。

### 1.2 不只有蛋白质：DNA、RNA、小分子、离子

细胞里真正干活的往往是**复合物（complex）**——多个分子抱在一起：

| 分子类型 | 小白理解 | 在 Protenix 输入里怎么写 |
|---|---|---|
| 蛋白质 | 干活的机器 | `proteinChain`：氨基酸字母串 |
| DNA | 遗传信息的"硬盘"，双螺旋，字母 A/T/G/C | `dnaSequence`（**单链**，双链要写两条互补链） |
| RNA | 信息"临时拷贝"或自身有功能，字母 A/U/G/C | `rnaSequence` |
| 小分子配体（ligand） | 药物、辅因子、代谢物等"小零件" | `ligand`：CCD 编号 / SMILES 化学式 / 结构文件 |
| 离子 | 如 Mg²⁺、Na⁺，常帮忙稳定结构或参与催化 | `ion`：如 `MG` |

- **SMILES**：用一行字符描述小分子化学结构的语法，例如 `CCO` 是乙醇。
- **CCD（Chemical Component Dictionary）**：PDB 维护的"化学零件字典"，每个已知小分子有一个 3 字符编号，如 `ATP`。Protenix 用的就是 `~/common/components.cif` 这个字典。✅

### 1.3 结构是怎么"真实测出来"的

- **X 射线晶体学、冷冻电镜（cryo-EM）、核磁共振**：昂贵（数月到数年、数十万美元量级）的实验方法。
- **PDB（Protein Data Bank）**：全球公开的实验结构数据库（约二十多万个结构），是所有结构预测模型的**训练数据和"标准答案"**。
- **分辨率**：数字越小越清晰，例如 1.8 Å 很清晰，3 Å 一般。1 Å（埃）= 0.1 纳米，大约是一个化学键的长度。

### 1.4 MSA 与"共进化"：为什么看亲戚能猜结构

这是理解 AlphaFold 系列的**最关键直觉**：

- **MSA（Multiple Sequence Alignment，多序列比对）**：把你的蛋白质在其他物种里的"同源亲戚"序列找出来，一行一条，按位置对齐。
- **共进化**：如果第 10 位和第 85 位在三维空间里紧挨着（互相接触），那么进化中第 10 位一突变，第 85 位往往也要跟着变才能维持结构。**在 MSA 里观察到"两列总是一起变"，就暗示这两个位置在空间上靠近**。
- 所以 MSA 就像"成千上万份同一道题的不同版本答卷"，模型从中统计出"谁和谁挨着"。**没有 MSA，模型几乎是在盲猜**——本文第二部分的 E3 实验会非常直观地证明这一点。
- **模板（template）**：如果 PDB 里已有相似蛋白的实验结构，可以直接拿来当"参考答案"。

## 2. Protenix 解决什么问题、有什么用

### 2.1 问题定义 ✅

给定一组分子（蛋白 / 核酸 / 配体 / 离子 / 共价键 / 修饰），预测它们形成的**复合物全原子三维结构**，并给出置信度。这就是 AlphaFold 3（AF3，2024 年 Nature）定义的任务，Protenix 是它的**可训练开源复现**。

### 2.2 应用场景 📘

| 场景 | 为什么需要结构 |
|---|---|
| **药物设计** | 看药物小分子能不能"塞进"靶蛋白的口袋、以什么姿势结合（结合构象 / pose） |
| **抗体工程** | 预测抗体与抗原（如病毒蛋白）的结合界面，优化抗体 |
| **蛋白设计** | 字节的 **PXDesign** 就是在 Protenix 基础上做"从头设计结合蛋白"，自报实验成功率 20–73% ✅⚠️ |
| **基础研究** | 理解蛋白-DNA 如何识别（如转录因子）、酶如何工作 |
| **替代/辅助实验** | 实验测一个结构要数月，模型几十秒到几分钟 |

### 2.3 生态 ✅

- **Protenix Web Server**（protenix-server.com）：网页版。
- **PXMeter**：开源评测工具 + 人工清洗过的基准集，Protenix 的官方评测就用它。
- **PXDesign**：基于 Protenix 的 binder（结合蛋白）设计。
- **Protenix-Dock**：不用神经网络的经典对接工具。

## 3. 基本哲学 / 设计思想

### 3.1 核心：在"同等条件"下公平、可复现、可训练地复现 AF3 ✅

AF3 原版的限制（📘）：DeepMind 在 2024 年发表时最初只提供网页服务，后来放出推理代码，但权重需申请、限制商用，**训练代码与训练数据管线不公开**——学术界没法在它基础上继续训练或改模型。

Protenix 的回答：

1. **全链路开源**：模型代码、推理、**训练代码、训练数据管线（2025-01-16 开源）、MSA 管线**、权重（v0.5 / v1）全部公开，Apache 2.0。✅
2. **严格对齐 AF3 的条件做对比**：v1 的 `protenix_base_default_v1.0.0` 使用和 AF3 **相同的训练数据截止日期（2021-09-30）、相近的模型规模（368M 参数）、相同的推理预算**（5 seed × 5 sample）。作者据此声称这是"第一个在多种基准上超过 AF3 的完全开源模型"。✅⚠️
3. **"双发布"策略**：同一架构发两个权重——`default`（截止 2021-09-30，用于**公平基准对比**）和 `20250630`（截止 2025-06-30，数据更新，用于**实际应用**）。✅ 这个设计很工程化：基准对比要防"考题泄漏"，实际使用要数据尽量新。
4. **推理时扩展（inference-time scaling）**：对难题（如抗体-抗原），把采样数从几个增加到几百个，精度近似**对数线性**上升——"用算力换精度"的旋钮。论文称 AF3 有此现象而此前开源模型基本没有。✅⚠️
5. **可扩展、可轻量化**：Mini/Tiny 小模型、约束（contact/pocket）输入、ESM 语言模型版本、多种 GPU kernel 可切换且各自有纯 PyTorch 回退。✅

### 3.2 与相关工作的关系

| 模型 | 时间 | 关系 / 差异 |
|---|---|---|
| AlphaFold2 📘 | 2021 | 只做**单个蛋白/蛋白复合物**；Evoformer + 结构模块（直接回归坐标）。Protenix 复用了 **OpenFold**（AF2 的开源可训练复现）中的部分模块实现 ✅ |
| AlphaFold3 📘 | 2024 | 扩展到**所有生物分子**；用 Pairformer 取代 Evoformer、用**扩散模型**生成坐标。Protenix 的代码文档直接引用 AF3 补充材料的算法编号 ✅ |
| Boltz-1 / Chai-1 📘 | 2024 | 同期其他 AF3 风格开源/开放复现。Protenix v0.5 的基准里与它们在 PoseBusters、核酸复合物、抗体集上做过对比 ✅ |
| Protenix | 2024– | 强调**可训练 + 条件对齐 + 训练管线开放**；v2 起转向更大模型与 binder 设计 |

## 5. 输入是什么、输出是什么

### 5.1 输入：一个 JSON 文件 ✅

格式接近 AlphaFold Server，但更宽松（任意 CCD 配体/修饰、支持 SMILES、支持实体间共价键）。完整规范见 `docs/infer_json_format.md`。一个最小例子（本仓库 `examples/example.json` 的 7r6r，一个蛋白 + 两条互补 DNA）：

```json
[{
  "name": "7r6r",
  "sequences": [
    {"proteinChain": {"sequence": "MGSSHHHHHHSSGLVPRGSH...", "count": 1,
                      "msa": {"precomputed_msa_dir": "./examples/7r6r/msa/1", "pairing_db": "uniref100"}}},
    {"dnaSequence":  {"sequence": "TTTCGGTGGCTGTCAAGCGGG", "count": 1}},
    {"dnaSequence":  {"sequence": "CCCGCTTGACAGCCACCGAAA", "count": 1}}
  ]
}]
```

| 字段 | 含义 |
|---|---|
| `proteinChain.sequence` / `count` | 氨基酸序列 / 拷贝数（同源二聚体就写 `count: 2`） |
| `modifications` | 翻译后修饰（某位置的残基换成某个 CCD 化学基团） |
| `pairedMsaPath` / `unpairedMsaPath` | 预先算好的 MSA（`.a3m`）。**可选但强烈建议**——没有它精度会暴跌（见实验 E3） |
| `templatesPath` | 模板检索结果（v1.0+） |
| `ligand` | `"CCD_ATP"` / SMILES 字符串 / `"FILE_xxx.sdf"` |
| `ion` | `"MG"` 等（注意**不加** `CCD_` 前缀） |
| `covalent_bonds` | 指定两个原子间共价键（如糖基化、共价药物、环肽） |
| `constraint.contact` / `pocket` | **软约束**：告诉模型"这两个残基/原子应在 X Å 以内"或"这个配体应结合在这些残基附近" |

配套工具：`protenix prep`（自动跑 MSA + 模板 + RNA MSA 检索并写回 JSON）、`protenix json`（FASTA/PDB/CIF → JSON）、`protenix msa` / `protenix mt`。✅

### 5.2 输出：结构文件 + 置信度 ✅

```
<out_dir>/<name>/seed_<seed>/predictions/
├── <name>_sample_0.cif                      # 排名第 1 的结构（按 ranking_score 降序）
├── <name>_summary_confidence_sample_0.json  # 它的置信度
├── <name>_sample_1.cif ...                  # 每个 seed 默认 5 个 sample
```

- **`.cif`（mmCIF）**：标准结构文件，每个原子一行 xyz 坐标，可用 PyMOL / ChimeraX / Mol* 打开查看。B-factor 列存的是 pLDDT。
- **置信度 JSON** 的主要指标（都是模型**自己估计**的，不是和真值比出来的）：

| 指标 | 范围 | 小白解释 |
|---|---|---|
| **pLDDT** | 0–100 | 每个原子"局部结构对不对"的自信度。>90 很可信，70–90 骨架大致对，<50 基本是乱的/天然无序区 |
| **PAE / PDE** | Å | "以 A 为参照看 B，位置误差多大"。用来判断两个结构域/两条链的**相对摆放**是否可信 |
| **pTM** | 0–1 | 整体折叠的可信度（基于 PAE 推出的 TM-score 估计） |
| **ipTM** | 0–1 | **界面**可信度：链与链之间的相对位置对不对。复合物最重要的指标；经验上 >0.8 较可信，<0.6 多半不对 |
| `chain_pair_iptm` 等 | — | 按链/链对细分的版本 |
| `has_clash` | 0/1 | 是否有链之间严重原子碰撞 |
| **ranking_score** | — | 用来给样本排序的综合分 |

`ranking_score` 的公式在 `protenix/model/sample_confidence.py:172`：

```
ranking_score = 0.8·ipTM + 0.2·pTM + 0.5·disorder − 100·has_clash     （代码中 disorder 恒为 0）
```

即"以界面可信度为主，整体折叠为辅，有碰撞直接判死刑"。

## 6. 基本实现思路（AF3 架构的通俗解读）

### 6.1 总流程图

```
输入 JSON
  │  ① 解析 + 分词（tokenize）
  ▼
token 序列（蛋白/核酸：1 残基 = 1 token；配体/修饰：1 原子 = 1 token）
  │  ② 嵌入：单体表示 s [N_token × 384]、成对表示 z [N_token × N_token × 128]
  ▼
┌──────────── 循环 N_cycle 次（base=10，mini=4）── recycling ─────────────┐
│  模板嵌入 → MSA 模块（4 块，读"亲戚"信息写进 z）                          │
│  → Pairformer（base 48 块：三角乘法 + 三角注意力 + 单体注意力）           │
└──────────────────────────────────────────────────────────────────────┘
  │  ③ 得到"理解"：s、z（谁和谁挨着、距离大概多少）
  ▼
扩散模块：从纯噪声的原子云出发，去噪 N_step 步（base=200，mini=5）→ 全原子坐标
  │  ④ 每个 seed 并行采样 5 个结构
  ▼
置信度头 → pLDDT / PAE / PDE / resolved → pTM / ipTM / ranking_score → 排序输出
```

✅ 代码对应：`protenix/model/protenix.py` 的 `get_pairformer_output`（① ② ③）、`protenix/model/generator.py` 的 `sample_diffusion`（④）、`protenix/model/sample_confidence.py`（置信度汇总）。数字来自 `configs/configs_base.py` 与 `configs/configs_model_type.py`。

### 6.2 逐个模块讲

**① 分词（Tokenization）** ✅ — `protenix/data/tokenizer.py`
标准氨基酸/核苷酸一个 token（一个"字"）；小分子和非标准残基每个原子一个 token。这让模型用**同一套机制**处理蛋白和药物——这是 AF3 能"什么都预测"的关键设计之一。

**② 两种表示：单体 `s` 与成对 `z`** ✅
- `s[i]`：第 i 个 token 自己的特征（是什么残基、在 MSA 里的分布……）。
- `z[i][j]`：token i 和 token j **之间关系**的特征（序列上隔多远、是否有共价键、是否被约束……）。
- 可以把 `z` 想象成一张 N×N 的"关系表 / 距离地图草稿"。**整个主干网络的核心工作就是不断改进这张表。**

**MSA 模块** ✅
把 MSA（亲戚序列）的共进化信号"灌"进 `z`：两列一起变 → 在 `z[i][j]` 上写"这俩可能挨着"。

**Pairformer + 三角更新** ✅📘
- 关键直觉是**三角不等式**：如果 i 离 k 近、k 离 j 近，那 i 和 j 不可能很远。三角乘法 / 三角注意力就是让 `z[i][j]` 参考所有"第三点" k 的 `z[i][k]`、`z[k][j]` 来自我修正，让距离草稿**几何上自洽**。
- 这部分计算量是 O(N³)，所以仓库里有多种加速 kernel（Triton `triattention`、NVIDIA `cuequivariance`、DeepSpeed、纯 torch），**设计上可互换、数值应一致**（第三部分实测：torch 与 triattention 两种 kernel 的差异落在同一 kernel 重复运行的随机波动范围内，但并非逐位相同）。

**Recycling（循环）** ✅
把上一轮输出的 `s`、`z` 加回下一轮输入，相当于"反复审题"。训练时只有**最后一轮**保留梯度（`protenix.py` 中 `cycle_no == N_cycle - 1`），省显存。

**③→④ 扩散模块：从噪声"雕刻"出原子坐标** ✅📘
- 和 Stable Diffusion 生成图片同理：训练时把真实原子坐标加不同程度的噪声，让网络学着"去噪"；推理时从完全随机的原子云出发，以 `s`、`z` 为条件逐步去噪成结构。
- 代码中的关键常数：`sigma_data = 16 Å`、推理噪声从 `s_max=160` 降到 `s_min=4e-4`、base 走 200 步。
- **为什么用扩散而不是直接回归坐标（AF2 的做法）？** 扩散天然能产出**多个不同的合理结构**（不同 seed、不同 sample），也更容易处理小分子这种"没有固定拓扑骨架"的东西。这也是"推理时扩展"能成立的前提：多采样 → 多候选 → 用置信度挑最好的。

**置信度头** ✅
另一个小网络，看着生成的结构和 `s`、`z`，预测"我这次大概错多少"：输出 pLDDT、PAE、PDE、experimentally-resolved 的分箱分布，再汇总成 pTM / ipTM。

### 6.3 训练：数据与损失 ✅

- **数据**：PDB 实验结构（mmCIF → 生物组装体 pickle，见 `docs/prepare_training_data.md`），外加**蒸馏数据**（用模型预测的高置信结构补充训练，如 MGnify 单体、无序区蒸馏）。训练时随机**裁剪**（连续/空间/界面裁剪，默认 crop 256 token）以控制显存。
- **对称性置换**：同一蛋白有两份拷贝时，预测的"A 链"可能对应真实的"B 链"——算损失前要先找最匹配的对应关系（`protenix/utils/permutation/`），否则会冤枉模型。
- **损失**（`protenix/model/loss.py` 的 `ProtenixLoss`，默认权重来自 `configs_base.py`）：

| 损失 | 权重 | 作用 |
|---|---|---|
| 扩散损失（加权 MSE + smooth lDDT + 键长） | 4.0 | 去噪后坐标要接近真值 |
| Distogram | 0.03 | 从 `z` 直接预测残基对距离分布，辅助主干学几何 |
| 置信度（pLDDT / PDE / PAE / resolved） | 1e-4 | 训练置信度头"诚实地"估计自己的误差 |

损失只在 trainer（`runner/train.py`）里计算，模型 `forward` 本身不算损失。

## 7. 性能与局限

### 7.1 性能（⚠️ 均为开发者自报）

- **Protenix-v1 vs AF3**：在 PXM-2024/2025（按年份切分、晚于训练截止日期，防考题泄漏）、FoldBench、Runs-N-Poses 等基准上整体超过 AF3。✅⚠️
- **评测协议**：对齐 AF3——5 seed × 5 sample = 25 个预测、recycle 10 次，按 ranking_score 选最佳。随机性来自 MSA 子采样、MC dropout（约 40% seed 上启用）和扩散轨迹本身。✅
- **推理时扩展**：抗体-抗原上采样从几个到几百个，精度近似对数线性提升。✅⚠️
- **Protenix-v2**：抗体-抗原 DockQ>0.23 成功率比 v1 绝对 +9~13 个百分点。✅⚠️

### 7.2 局限（作者承认 + 研究发现）

1. **在 FoldBench 上，AF3 在蛋白-配体、蛋白-DNA 对接上仍领先**（如 64.90 vs 62.79、79.18 vs 73.29）；Protenix-v1 的优势在蛋白-蛋白和抗体-抗原界面，但只领先约 1–2 个点，在运行方差范围内。✅（作者对自己不利的承认，可信度较高）
2. 基准多为作者自建（PXM 系列），**缺少独立第三方复现**。⚠️
3. v2 **权重闭源**，外界难以核验其结果；v2 的 binder 设计功能目前未在本仓库开放。✅
4. 置信度（ipTM / ranking_score）与真实精度的**校准程度**是否足以支撑药物决策，仍是开放问题——本文第三部分的抗体-抗原实验中，ranking_score 与真实 DockQ 的相关系数为 −0.16 / −0.09，**完全挑不出正确的结构**。
5. 📘 所有 AF3 类模型的共同限制：预测的是**一个静态构象**（真实蛋白会动）；对训练集中罕见的类型（新颖折叠、孤儿蛋白——MSA 很浅）效果差；配体位置可能"看起来合理但化学上不对"。

### 评估方法（`experiments/eval_vs_ground_truth.py`，自写简化版，非官方 PXMeter）

- **链匹配**：按 label_seq_id 逐位比对残基名把预测链对应到真值链；同源拷贝（如两条相同蛋白）穷举排列，取代表原子 RMSD 最小者。
- **RMSD（Å，越小越好）**：全局叠合后蛋白 Cα / 核酸 C1′ 原子的均方根偏差。对"整体摆放"敏感——一个结构域歪了，RMSD 就会被拉高。
- **lDDT（0–1，越大越好）**：不需要叠合，比较每个原子周围 15 Å 内的距离是否保持（容差 0.5/1/2/4 Å 取平均）。更关注**局部**是否正确，是 AF 系列的标准指标（pLDDT 就是在预测它）。
- **界面 lDDT**：只统计**不同链之间**的原子对——衡量"分子之间抱得对不对"。
- **配体口袋 RMSD**：用真值中配体 10 Å 内的蛋白/核酸骨架原子做局部叠合，再算配体重原子 RMSD。业内常用 **< 2 Å 视为成功**。
- 局限：未做对称原子交换（如苯环翻转）、未算 DockQ，核酸的统计半径用了 15 Å（AF3/PXMeter 用 30 Å），数值仅供相对比较。【更正】第三部分已改用官方工具 PXMeter 重新评估全部结构。

## 12. 结果解读（给小白）

1. **MSA 是命根子（E3）**。同一个模型，拿掉"亲戚序列"后，三个目标全部崩溃：RMSD 从 ~1 Å 变成 20–25 Å（基本是乱的），7wux 的界面 lDDT 从 0.76 掉到 0.05。而且**模型自己知道**——pLDDT 从 ~90 掉到 33–62，ipTM 掉到 0.2–0.5。这正是 1.4 节"共进化"直觉的实证。
2. **置信度是"诚实"的**。E2 在 7r6r 上 ipTM 只有 0.57，真实界面 lDDT 也只有 0.54；E1 ipTM 0.92，真实界面 lDDT 0.81。**看 ipTM 基本能判断这次预测能不能信**——这是使用这类模型时最重要的实用技能。
3. 【更正：此对比有混杂，见第三部分 15 节】**大模型赢在"难题"上，简单题差不多（E1 vs E2）**。7pzb、7wux 的蛋白部分两者几乎打平；但在蛋白-DNA 识别的 7r6r 上，mini 的界面明显错位（RMSD 3.2 Å vs 1.2 Å），而 mini 在大体系上快约 4 倍。→ 高通量初筛用 mini，关键目标用 base。
4. **RMSD 与 lDDT 讲的是不同的故事（7wux）**。7wux 的 lDDT 高达 0.88（局部都对），RMSD 却有 3.6 Å。【更正】原解释"链之间有轻微偏移"不对：PXMeter 显示 base v1 把两条相同蛋白（A、B）之间的**二聚体界面整个预测错了**（DockQ 仅 0.32）；而该四聚体是作者经凝胶过滤验证的生物学组装，所以这是真错误，不是晶体伪影。看结构要同时看局部和整体。
5. **小分子比蛋白难，排序分对配体姿势的分辨力有限（7wux 的 6OI）**。base v1 的 5 个 sample 里有 2 个把 6OI 放对了（1.2–1.5 Å），但排名第一的那个错了 7 Å，而它们的 ranking_score 只差 0.001。ranking_score 主要由 ipTM（整条链的界面）决定，一个小配体放错几乎不影响它。mini 这次碰巧排第一的是对的，**单 seed 下不能据此说 mini 更会放配体**。实际药物设计中应多采样，并单独检查配体相关指标（或用 `need_atom_confidence` 看配体原子的置信度）。
6. **cGMP（7pzb）放得很准**：两个模型都在 1.2–1.4 Å，属于"成功"。
7. **P4G 与部分 Mg²⁺ 偏差巨大并不意外**（以下为**推测**，未核实原始论文）：P4G 是 PEG 类结晶添加剂，在晶体里往往贴在随机的表面或晶格接触处，本身没有"正确答案"；3 个 Mg²⁺ 中 base v1 通常能放对 2 个（≈2 Å），另一个总是偏离很远，推测同样不在功能位点。这提醒我们：**"标准答案"本身也有实验伪影**，这正是 PXMeter 要人工清洗基准集的原因。
8. 【更正：结论被推翻，见第三部分 16 节——换用 DockQ 并做随机重抽样后，多采样在 7r6r 上**有**小幅收益】**推理时扩展在"简单题"上没有收益（E4）**。7r6r 对 base v1 来说已经很容易（第一个样本就 1.2 Å），把采样从 5 加到 50，模型自选的结果反而略差（1.22→1.62 Å，界面 lDDT 0.812→0.807），虽然 50 个里确实存在更好的（0.827）——排序分在一堆"都还不错"的候选里分不出细微优劣。论文中的对数线性提升是在**抗体-抗原这类难题**上观察到的；本实验与之不矛盾，而是说明：**多采样的主要价值是在难题上"捞到"正确解、以及避开坏 seed，而不是在已解决的问题上锦上添花**。

1. **大权重不能直接拿来少步采样**。base v0.5 的权重配上 mini 的采样设置（同样 gamma0=0、5 步），结构直接坏掉：相邻 Cα 原子平均相距 9.6 Å，真实应为 3.8 Å，lDDT 只有 0.24。DockQ 还有 0.5 左右，是因为链的大致位置没错。也就是说，**mini 能用 5 步出结构，这个能力在 mini 自己的权重里**，不是靠采样设置得来的。所以"同权重、换预算"这一行不能用来衡量模型大小的影响。

5. **MSA 依旧是关键**：无 MSA 时所有界面的 DockQ 都低于 0.07，与第二部分的结论一致。

## 16. 多采样（推理时扩展）重做

**方法**：从全部 seed 中随机抽 k 个，取这 k×5 个样本里 ranking_score 最高的那个（"模型自选 top-1"），同时记录这些样本里真实最好的那个（"oracle"，现实中拿不到，作为上限参考）。每个 k 重复抽 2000 次取平均。第二部分只按 seed 顺序算了一遍，结果受偶然性影响大，这里改正了这一点。

### 16.1 简单题 7r6r（10 seed，指标：蛋白-DNA 界面 DockQ）

| seed 数 k | 样本数 | 模型自选 top-1 均值 | oracle 均值 |
|---|---|---|---|
| 1 | 5 | 0.696 | 0.723 |
| 2 | 10 | 0.712 | 0.753 |
| 5 | 25 | 0.731 | 0.772 |
| 10 | 50 | 0.738 | 0.779 |

全部 50 个样本的 DockQ 在 0.453–0.779 之间，ranking_score 与 DockQ 的 Pearson 相关为 0.57。

**【更正】** 第二部分说"多采样在简单题上没有收益、甚至略差"，这个结论被推翻了。换成更合适的界面指标、做了随机重抽样之后，模型自选的结果随采样数**单调小幅上升**（0.696 → 0.738）。原来的结论来自"单一顺序 + 单个指标"的偶然性。

4. **与论文结论的关系**：论文报告的是在大量抗体-抗原数据集上，**成功率**随采样数近似对数线性提升。本实验只有 2 个目标，关了模板，MSA 也来自服务器，**不足以否定**论文的结论。它说明的是：对某些具体目标，正确答案虽然能被采到，但瓶颈在**排序（挑选）**而不在**采样**。实际使用时，可以考虑用实验信息（比如已知的表位）做约束，或者把多个候选都交给下游去验证。

## 17. 换 kernel 会不会改变结果（K1）

同一个 seed，用 `triattention` 和 `torch` 两种三角注意力 kernel 各跑一次 7r6r，按样本逐一比较坐标：

| 比较 | 5 个样本的平均原子偏差 | ranking_score 差异 |
|---|---|---|
| torch vs triattention（换 kernel） | 0.12 / 0.14 / 0.17 / 0.40 / 1.51 Å | ≤ 0.0003 |
| triattention vs triattention（同 kernel 重跑：E1 vs E4 的 seed 101） | 0.08 / 0.15 / 0.30 / 0.83 / 2.10 Å | — |

**结论**：换 kernel 带来的差异，落在同一个 kernel 重复运行的随机波动范围之内（这种波动来自 GPU 的非确定性，又被 200 步扩散放大）。所以"kernel 不改变结果"在统计意义上成立，但**并非逐位相同**，同一个 seed 也不能逐位复现。只在 1 个目标上比较了 torch 和 triattention，没有测 cuequivariance（未安装）。

| "GPU 非确定性带来的差异极小" | 只看了 top-1 RMSD | 逐样本比较，平均偏差最高达 2.1 Å |
| "kernel 数值等价" | 没有验证 | 第 17 节：统计上等价，并非逐位相同 |
| "训练时没见过这些结构" | 说过头了，训练集可能有同源蛋白 | 已改为"这个具体结构不在训练集里" |
| P4G / Mg²⁺ 的解释 | 是推测，却写得像结论 | 已标注为推测 |
| 评估脚本是简化版 | 无对称原子、无 DockQ、核酸半径不对 | 全部 690 个结构改用 PXMeter 重新评估 |
| 依赖装进了系统 Python | 可能影响共用环境的其他任务 | 新装的 PXMeter 已放进独立 venv；**前一天装进系统的 Protenix 依赖还在**，没有回滚（回滚可能反过来影响 GPU 0–4 上正在跑的任务，需要你来决定） |

## 19. 仍然存在的局限

- 受控对照只有 3 个目标，抗体-抗原只有 2 个目标，结论都是示例性的。
- 全程关闭了模板（机器上没有 hmmer/kalign 和 PDB seqres 数据库），v1 没有发挥全部能力。
- 没有测试 cuequivariance kernel、约束模型、v2（权重不开放）。
- 没有做 PoseBusters 化学合理性检查（PXMeter 支持，但默认关闭）。
- 这台机器上 Protenix 依赖的 torch 2.8 不是官方钉住的 2.7.1 版本。所有实验都正常跑完了，但没有和官方环境做数值对比。

## B. 如何自己看结构

把 `experiments/E1_base_v1/7r6r/seed_101/predictions/7r6r_sample_0.cif` 和 `experiments/ground_truth/7r6r.cif` 一起拖进 [Mol*](https://molstar.org/viewer/) 或 PyMOL，叠合后即可肉眼对比；按 B-factor 着色即可看到 pLDDT（蓝=自信，橙/红=不自信）。
